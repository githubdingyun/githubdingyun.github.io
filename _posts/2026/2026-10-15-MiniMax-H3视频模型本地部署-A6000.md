## 一、MiniMax H3 是什么

MiniMax H3 是 MiniMax 于 2026 年 7 月底发布的 **33B 参数多模态视频生成模型**，8 月在 Hugging Face 开源权重（`MiniMaxAI/MiniMax-H3`）。核心能力：

| 维度       | 规格                                       |
| -------- | ---------------------------------------- |
| 输入       | 文本 / 图片 / 音频 / 视频（多模态参考）                |
| 输出       | 视频 + **原生立体声音频**（一次生成同时出）               |
| 最高分辨率    | 完整 H3 系统最高 2K；**开源 H3-Base 固定 768p 短边**（2K 依赖未开源的 H3-Regenerate-2K） |
| 时长       | 4–15 秒（按 `17k+5` 帧网格、24fps 对齐，最大 362 帧）；\~30 秒是托管 API 的延长能力，H3-Base 不支持 |
| 画幅       | 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 等   |
| 参考素材     | 最多 9 图 + 3 视频 + 3 音频（合计最多 12 个文件）      |
| 文本编码器    | Qwen3-VL-32B                             |
| 开源权重     | 每个 checkpoint 分区磁盘约 135 GiB（含完整 BF16 权重） |

### 1.1 两个 Base checkpoint

| Checkpoint | 用途                 | 说明                                              |
| -------- | ------------------ | ----------------------------------------------- |
| **FL2VA** | 文生音视频 / 首尾帧控制      | 主力，Text-to-Video + 首尾帧（First-Last-2-Video-Audio） |
| **Ref2VA** | 参考图/视频/音频生成        | 角色一致性、动作迁移，最多 9 图 + 3 视频 + 3 音频                |

**结论**：日常出片用 **FL2VA**；要「锁角色」（同一角色跨镜头一致）或动作迁移，加 **Ref2VA**。

## 二、视频模型调研与竞品对比

### 2.1 主流视频模型对比（2026）

| 模型                | 最高分辨率           | 时长              | 原生音频   | 开源    | 价格（API）             |
| ----------------- | --------------- | --------------- | ------ | ----- | ------------------- |
| **MiniMax H3**    | 2K（开源 Base 768p） | 4–15s（API 可延至 \~30s） | ✅ 立体声  | ✅ Base | 768P \~$0.08/s，2K \~$0.13/s |
| Wan 3.0（阿里）       | 1080p           | 最长 30s          | ✅      | ✅     | \~$0.054/s          |
| Kling 3.0（快手）     | 1080p（Pro 4K）   | 3–15s，6 镜头      | ✅      | ❌     | $0.084–0.168/s      |
| Veo 3.1（Google）   | 4K              | 8s/段，拼 60s+     | ✅      | ❌     | $0.05–0.60/s        |

### 2.2 H3 的差异化卖点

H3 不追求绝对最高画质（4K 上 Kling Pro / Veo 更狠），它的卖点是：

* **Omni-Reference 多素材控制**：一次喂 9 图 + 3 视频 + 3 音频，角色 / 动作 / 风格全锁。

* **原生音频**：视频和立体声音频（对白、音效、音乐）同一次生成出来，不用后期配音。

* **指令式编辑**：Artificial Analysis 盲测视频编辑榜第 1（Elo 1130）、带音频文生视频第 2、图生视频第 3。

* **开源可自部署**：Base 权重开放，48GB 显存能跑，数据不出内网。

### 2.3 结论

| 场景                    | 选谁                          |
| --------------------- | --------------------------- |
| 本地自用、数据不出内网          | **MiniMax H3**（开源，A6000 能跑） |
| 追求 4K 极致画质、不在乎 API 费用 | Veo 3.1 / Kling 3.0 Pro     |
| 长视频（30s+）             | Wan 3.0 / Veo 3.1（可拼接）      |
| 角色一致性 + 原生音频          | **MiniMax H3 Ref2VA**       |

## 三、部署方式对比

### 3.1 主流部署工具对比

| 方式                          | 难度         | 硬件门槛              | WebUI           | 适合场景           |
| --------------------------- | ---------- | ----------------- | --------------- | -------------- |
| **ComfyUI**（原生 0.30.0+）     | ⭐⭐ 中等     | 社区实测 16GB 起（24GB 舒适；官方未公布最低显存） | 节点式，工作流丰富       | **个人自用首选**     |
| SGLang（官方参考配置）             | ⭐⭐⭐⭐ 专业  | 官方参考 8×B200（非最低要求） | API             | 数据中心、生产        |
| vLLM-Omni                   | ⭐⭐⭐ 专业   | 多卡                | API（`/v1/videos`） | 服务化、多并发        |
| 一键整合包（ComfyUI 后端）          | ⭐ 极简     | 8GB 显存起           | 内置              | 新手、低显存         |
| ONNX 版                      | ⭐⭐       | 4GB 显存起           | WebUI :7860     | 极致低配           |

### 3.2 为什么选 ComfyUI

* **原生支持**：ComfyUI 0.30.0+ 内置 MiniMax H3 节点，无需第三方插件。

* **工作流灵活**：T2V / I2V / 首尾帧 / Ref2VA 都有现成工作流，可自由改参数。

* **显存友好**：int8 量化 + 分层 offload，社区实测 16GB 显存能跑；48GB 可容纳全部 int8 权重，但余量不算宽裕。

* **生态成熟**：节点生态丰富，方便接 LoRA、ControlNet、超分等。

SGLang / vLLM-Omni 是数据中心方案（官方参考配置 8×B200，也支持多卡/消费级 offload），个人自用没必要；一键整合包省事但灵活度低；ONNX 版适合 4GB 显存的极限场景。

## 四、A6000 48GB 选型建议

A6000 48GB 显存 + 64GB 内存，是跑 H3 的**舒适区**：

| 档位                 | 权重占用（实测文件）                                   | 能否全显存加载          | 可跑规格                    |
| ------------------ | -------------------------------------------- | ---------------- | ----------------------- |
| pruned int8（推荐）    | 模型 20.97GB + 编码器 15.69GB + 视频 VAE 5.21GB + 音频 VAE 0.61GB ≈ **42.5GB** | ✅ 能，但余量约 5GB，需按需加载/卸载 | 1344×768 / 15s（开源 Base 上限） |
| 全精度 BF16          | 模型 66.3GB + 编码器 51.5GB + VAE ≈ **123GB** | ❌ 需多卡 / offload | —                       |

**建议**：

* **推理框架**：ComfyUI（portable 版，解压即用）。

* **checkpoint**：FL2VA（pruned int8 convrot）为主，Ref2VA 按需加。

* **量化**：int8 convrot（显存 / 质量平衡最好）。

* **分辨率**：日常 1280×704 或 1344×768（这是开源 Base 的原生上限，别按 2K 规划）。

* **内存**：64GB 够用；offload 仅作备用。

48GB 显存的优势：**int8 权重能整体放进显存**（约 42.5GB），不必像 16/24GB 卡那样频繁在显存和内存之间换入换出；但只剩约 5GB 给激活值，长时长/高分辨率时建议让 ComfyUI 按需卸载文本编码器。

## 五、部署步骤（ComfyUI 方案）

### 5.1 装 ComfyUI（portable 版）

```
# 下载 ComfyUI portable（Windows 解压即用）
# 官网 https://comfyui.com 或 GitHub https://github.com/comfyanonymous/ComfyUI
# 解压到 D:\ComfyUI（别放 C 盘，模型文件大）

# 确认 GPU 识别
nvidia-smi
```

> 要求 ComfyUI ≥ 0.30.0（原生支持 H3）。portable 版自带 Python 环境，无需单独装。

### 5.2 下载模型文件

模型来自 Hugging Face `Comfy-Org/MiniMax-H3`（国内用 ModelScope / hf-mirror 镜像更快）。**48GB 显存下载 pruned int8 版**：

| 文件                                                        | 放置目录                     | 大小       |
| --------------------------------------------------------- | ------------------------ | -------- |
| `minimax_h3_fl2va_pruned_int8_convrot.safetensors`        | `models/diffusion_models/` | 20.97 GB |
| `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`            | `models/text_encoders/`    | 15.69 GB |
| `minimax_h3_video_vae_fp16.safetensors`                   | `models/vae/`              | 5.21 GB  |
| `minimax_h3_audio_vae_fp32.safetensors`                   | `models/vae/`              | 0.61 GB  |
| `minimax_h3_ref2va_pruned_int8_convrot.safetensors`（可选）   | `models/diffusion_models/` | 20.97 GB |

```
# 用 huggingface-cli 下载（国内配镜像）
pip install -U huggingface_hub
set HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download Comfy-Org/MiniMax-H3 `
  --include "minimax_h3_fl2va_pruned_int8_convrot.safetensors" `
  --local-dir D:\ComfyUI\models\diffusion_models
```

> 总下载量 ≈ **42.5GB**（FL2VA + 编码器 + VAE），加 Ref2VA 再 +21GB（可选）。磁盘留 70GB+ 空间。

### 5.3 启动 ComfyUI

```
# 48GB 显存，全量加载，正常启动
D:\ComfyUI\run_nvidia_gpu.bat

# 浏览器打开 http://localhost:8188
```

> 48GB 显存无需 `--lowvram` / `--medvram`，默认全显存加载即可。若显存吃紧可加 `--vram-headroom 2`。

### 5.4 加载工作流

ComfyUI 0.30.0+ 内置 H3 工作流模板：

```
Workflow → Browse Templates → Video → 选 MiniMax H3
```

或用**社区现成工作流**（来自第三方仓库，非官方模板）：

* **T2V**（文生视频）：`MATLOWAI-01_reference_4step_sla.json`

* **I2V / 首尾帧**：`MATLOWAI-04_i2v_fl2v_4step_sla.json`

* **Ref2VA**（参考图锁角色）：`MATLOWAI-05_ref2va_4step_sla.json`

## 六、示例

### 6.1 文生视频（T2V）

**Prompt**：

```
一只金毛犬在阳光下的草地上奔跑，毛发随风飘动，
镜头跟随，电影感，浅景深，暖色调
```

**参数**（A6000 48GB 推荐；下表是社区工作流实测配置，官方模板默认 20 步）：

| 参数            | 值                        | 说明                    |
| ------------- | ------------------------ | --------------------- |
| 分辨率           | 1280×704                 | 32 的倍数，48GB 可上 1344×768 |
| 帧数            | 124（@24fps ≈ 5.2s）       | 最长 362 帧（15s）         |
| 采样器           | `res_multistep`          | 社区工作流配置              |
| 步数            | 25（官方模板默认 20）            | 质量 / 速度平衡；8 步 Turbo LoRA 更快但质量下降 |
| CFG           | 4.0                      | 社区工作流配置              |
| 调度器           | `simple`                 | —                     |
| denoise       | 1.0                      | 文生视频固定 1.0            |
| SigmaShift    | 视频 12.0 / 音频 3.0         | MiniMaxH3SigmaShift 节点  |
| MotionContext | context 22 / audio 24    | MiniMaxH3MotionContext 节点 |

**输出**：5 秒视频 + 原生立体声音频（环境音）。

### 6.2 图生视频（I2V）

给一张静态图，让它动起来：

1. 工作流选 `MATLOWAI-04_i2v_fl2v_4step_sla.json`。

2. 把图片拖入 Load Image 节点。

3. 加一句 prompt 描述运动：「人物缓缓转头，头发飘动」。

4. 参数同 T2V（denoise 可降到 0.8–0.9 保持原图风格）。

**首尾帧控制**：给首帧 + 尾帧两张图，H3 自动补中间过渡，适合做转场。

### 6.3 参考图锁角色（Ref2VA）

同一角色跨镜头保持一致：

1. 工作流选 `MATLOWAI-05_ref2va_4step_sla.json`。

2. 加载 Ref2VA checkpoint（`minimax_h3_ref2va_pruned_int8_convrot.safetensors`）。

3. 喂角色参考图（最多 9 张）+ 动作参考视频（最多 3 个）。

4. prompt 描述场景，角色外观由参考图锁定。

**典型用途**：AI 漫剧、虚拟人连续剧、产品广告（同一模特多角度）。

### 6.4 分阶段出片（省时间）

正式出片前先用低配预览，确认构图 / 运动再上高配：

| 阶段  | 分辨率       | 步数       | 用途           |
| --- | --------- | -------- | ------------ |
| 预览  | 832×480   | 8–12     | 快速看构图、运动     |
| 中档  | 1024×576  | 16–20    | 确认细节         |
| 成片  | 1344×768  | \~20     | 最终输出         |
